# 003 — No hand-labelling. Ground truth is generated, not annotated.

**Date:** 2026-08-06
**Status:** Decided. Supersedes option B of
[decision 002](002-scoring-against-a-noisy-oracle.md).
**Blocks:** M1 (baselines), M2 (injection harness)

---

## The question

Decision 002 proposed hand-labelling a gold set of narratives to establish which `XXXX` markers
are genuinely personal information, and using it as the referee that ranks the other scoring
conventions by accuracy.

Should this project contain a manual annotation step?

## The decision

**No. There is no hand-labelling anywhere in this project.**

Two reasons, and the second is stronger than the first.

### 1. It is the wrong shape of work

The engineering claim this portfolio is making is about building systems. A manual annotation
step is a different job, and a portfolio project that only works if someone spends a weekend
annotating spans has a dependency it should have engineered away.

### 2. The brief already ruled it out, and decision 002 missed it

The project brief specifies three headline numbers and then says of them:

> *"Three numbers, all measurable, none requiring a human **or a model** to judge anything."*

Decision 002 proposed exactly the thing that sentence excludes. That was an error on my part —
I treated hand-labelling as the rigorous option without checking it against the brief's own
design constraint. The brief had already solved this problem, in section 4:

> *"To get labels that are exact rather than noisy: take narratives that are already scrubbed,
> insert personal information we generated ourselves at positions we recorded... Those labels
> are facts, not opinions — we wrote them down when we put them in."*

**Injection is the ground truth.** It is exact, it is generated by committed code from a fixed
seed, it regenerates from scratch in `make repro`, and nobody has to judge anything.

Note what this makes of the objection: the answer to "we need labels" is *build a labelling
system*, not *label by hand*. That is the systems answer, and it is the more interesting one.

## What this buys

Injecting into the **40,319 narratives with no markers at all** yields both halves of ground
truth from one construction:

| | how we know | exact? |
|---|---|---|
| **Positives** | We inserted this PII at this character offset. We wrote it down. | Yes |
| **Negatives** | The rest of the text is what a CFPB redactor already passed as clean | Yes, modulo the assumption below |

The negatives are what makes precision measurable. The assumption they rest on — that a
narrative a human marked zero times contains no PII — is far weaker than the assumption
decision 002 needed, which was that every *individual* marker is correct. Judging a whole
narrative clean is one decision; trusting 184,633 individual markers is 184,633 of them.

## What this costs, stated plainly

**We can no longer rank scoring conventions A, C and D by accuracy.** That capability required
knowing what individual markers were, and without labels we do not and cannot know. Decision
002's ranking instruction is not executable and is withdrawn rather than quietly approximated.

Consequences, all of which get published:

1. **Recall against `XXXX` markers stays a lower bound with an unmeasured gap.** We know the
   oracle over-redacts; we cannot say by exactly how much. Every recall figure says so.
2. **Over-redaction is lower-bounded mechanically, not measured.** Where surviving context
   determines the type — `XXXX bureaus`, `XXXX points`, `XXXX %`, `XXXX CFR` — a committed rule
   set counts them. That yields "at least N% of narratives contain a non-PII marker". The true
   rate is higher, and the number is labelled a floor everywhere it appears.
3. **Conventions A, C and D are all still reported**, as alternative views with the filter rules
   committed and readable. They are simply presented side by side rather than ranked, and
   `docs/03-baselines.md` says why the ranking is absent.

## The trap this decision must not fall into

There is an obvious-looking substitute for hand labels: treat **baseline consensus** as truth —
if Presidio, spaCy and regex all decline to flag a marked span, call that span over-redaction
and drop it from the oracle.

**This must not be done, and the reason is worth writing down.** The spans all three baselines
miss are precisely the contextual identifiers — "my ex-husband", "the Fremont branch" — that
Airlock exists to catch. Filtering the oracle by baseline consensus would delete the project's
entire test set for its central claim and replace it with the subset the baselines already win.
The measured improvement would then be near zero by construction, and it would look like a
finding.

Baseline agreement is reported as an interesting statistic in `docs/03-baselines.md`. It is
never used to modify the oracle.

## Consequences for the plan

- M2 (injection) is promoted from "gives precision" to "gives all exact ground truth", and is
  now a hard dependency of every precision and category-accuracy number in the project.
- The injection distribution still has to be derived from the real corpus, per the brief. M0's
  context mining supplies it.
- `DEFINITIONS.md` is amended, dated, with this file as the reason.
